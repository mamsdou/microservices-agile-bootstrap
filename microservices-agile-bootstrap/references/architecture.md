## Overview

```
Browser → frontend (nginx :4200) → api-gateway (:8080) → business services (:8081…)
                                        │                    │        │
                                   discovery (:8761)    PostgreSQL   Kafka (KRaft)
                                   config-server (:8888)  (1 DB per service)
JSON logs (TCP :5000) → Logstash → Elasticsearch → Kibana (:5601)
```

The first business service publishes `<service>.events`; the others consume that topic (group = service name). This is a sample flow to replace with the domain's real events.

## Versions and compatibility

Defined at the top of `scripts/scaffold.py`: Spring Boot 3.3.5 ↔ Spring Cloud 2023.0.3 (this pair is compatible; Spring Cloud 2024.0 requires Boot 3.4 and changes the Gateway property prefix to `spring.cloud.gateway.server.webflux`). Angular 15.2 requires Node 14.20, 16 or 18 (the Dockerfile uses Node 18). Elastic 8.15, Kafka 3.8 (`apache/kafka` image), PostgreSQL 16. If you change Boot, change Spring Cloud with it and check the official compatibility table.

## Naming conventions

For a `user-profile` service: module `user-profile-service`, class `UserProfile`, REST resource `/api/user-profiles`, table `user_profiles`, database `user_profile_db`, topic `user-profile.events`, package `<groupId>.userprofile`.

## Configuration flow

Each module has a minimal local `application.yml` (name, port, `optional:` Config Server import). Everything else comes from `config-server/src/main/resources/config-repo/` (shared `application.yml`, `<service>.yml`, `api-gateway.yml`). In production, replace the `native` backend with a Git repository (ADR-0002). The `${VAR:default}` placeholders in config-repo files are resolved on the client side: this keeps the same files for local, Compose and Kubernetes.

## Adding a service

Rerunning the script with `--force` would overwrite the folder: prefer copying an existing service (`services/<x>-service`), renaming package/classes/table/migration, then updating: `<parent>/pom.xml` (modules), `config-repo/<new>.yml`, `config-repo/api-gateway.yml` (route), `infra/docker/init-db.sql`, `docker-compose.yml`, `k8s/` (new file + `kustomization.yaml`), `frontend/src/app/app.component.ts` (`resources` list), `docs/architecture/` and an ADR if the service brings a structural decision.

## Security (Keycloak)

- Realm = project name, public client `<project>-frontend` (code + PKCE), one dev user per role (password `dev-<role>`, local use only). The realm is generated by `scaffold.py` (`keycloak_realm`) in `infra/keycloak/realm.json` and imported by `start-dev --import-realm`.
- Gateway (WebFlux): `authenticated()` on `/api/**`. Services (servlet): `SecurityConfig` + `KeycloakRoleConverter` (`realm_access.roles` → `ROLE_<name>`), rights read from `app.security.write-roles` / `read-roles` in `config-repo`. A write role can also read.
- The issuer claim must be identical for the browser and the services: Keycloak runs with `KC_HOSTNAME=http://localhost:8180`; services validate `iss` with `KEYCLOAK_ISSUER` but read keys with `KEYCLOAK_JWKS` (internal address `http://keycloak:8080`). If valid tokens are rejected (401), check this first.
- Angular: `angular-oauth2-oidc`; `frontend/src/config.js` (Keycloak URL, realm, client) can be overridden without rebuilding the image (`frontend-config` ConfigMap in Kubernetes).
- Roles do not protect data ownership (a customer sees everything their role can read): plan a dedicated story based on the `sub` claim.
- Adding a service or role: rerun the script logic or manually edit `realm.json` (roles, users), `config-repo/<service>.yml` (roles) and `docs/architecture/06-security.md`.

## Known pitfalls

- Keycloak (image `quay.io/keycloak/keycloak:25.0.6`) has not been started during skill testing: `KC_HOSTNAME` and the realm import must be validated at first startup.
- Flyway 10 (Boot 3.3) requires `flyway-database-postgresql` in addition to `flyway-core`: already in the POMs.
- A service started before the Config Server has neither datasource nor Kafka: Compose uses `depends_on … service_healthy`; outside Docker, start config-server then discovery-server first.
- Events are published after commit (`@TransactionalEventListener`), but with no guarantee if the broker is unavailable at that moment: the Outbox pattern is the logical next step (ADR-0005, backlog story).
- Elasticsearch runs without security in dev (`xpack.security.enabled=false`): do not expose it. Compose publishes ports on `127.0.0.1` only.
- The generated Kubernetes secrets are encoded dev values, not encryption.
